1. Overview

StorageGRID hardware appliances are purpose-built servers that run as dedicated grid nodes instead of virtual machines. This tutorial covers the two appliance families you asked about:

Services Appliance

SG100 (and SG1000)

Runs as a Gateway Node and/or Admin Node. Provides S3/Swift load-balancing and grid management — it has no bulk object storage of its own.

Storage Appliance

SG6060 (SG6000 family)

Runs as a Storage Node. Combines a compute controller with an E‑Series storage shelf to provide object storage capacity (up to 180 drives with expansion shelves).

About "SG6112": The StorageGRID 11.5 documentation set used for this tutorial does not include an "SG6112" model — that name doesn't appear in the 11.5 manuals. The closest, similarly-purposed appliance in this hardware family is the SG6060 (60-drive, expansion-capable) or the SGF6024 (24-SSD all-flash). A unit called the SGF6112 (single-controller, all-flash) was introduced in a later StorageGRID release, so its specifics aren't in this document set. Everything below for the "6000 series" architecture (compute controller + E-Series storage shelf, Fibre-Channel interconnect, SANtricity-managed controllers) is structurally how that whole family — SG6060, SGF6024, and later SGF6112 — is built, even though exact drive counts/connectors differ per model.

2. SG100 Architecture

The SG100 is a 1U services appliance. From the front it's nearly identical to the larger SG1000 (which supports higher network speeds) — they differ only in badge and port speed.

Internal components

  • Two solid-state drives (SSDs) — mirrored with RAID1 — store the StorageGRID OS and, when the node acts as an Admin Node, audit logs / metrics / database tables.
  • A baseboard management controller (BMC) for out-of-band hardware monitoring (IPMI).
  • Redundant power supplies.

Rear connectors

Network ports 1–410/25-GbE (SFP+/SFP28)Grid Network and Client Network traffic
BMC management port1-GbE RJ-45Out-of-band hardware management
Diagnostic portsVGA / Serial / USBReserved for technical support
Admin Network port 11-GbE RJ-45Connect to the Admin Network
Admin Network port 21-GbE RJ-45Bond with port 1 for redundancy, or leave free for temporary local access at 169.254.0.1

(The SG1000 is identical except network ports 1–4 also support 40/100-GbE via QSFP+/QSFP28.)

Deployment roles

  • Gateway Node (load balancing for S3/Swift client traffic)
  • Admin Node — primary or non-primary
  • Both roles simultaneously on the same unit
  • Two units can be paired into an HA group with a shared virtual IP for highly-available load balancing
Do not mix SG100 and SG1000 appliances at the same site — unpredictable performance can result.

3. SG6060 Architecture (SG6000 family)

The SG6060 is built from two physical enclosures that work together as a single Storage Node:

ComponentDescription
SG6000-CN compute controller (1U) 40 cores / 80 threads, 192 GB RAM, up to 4×25 Gbps aggregate Ethernet, 4×16 Gbps Fibre Channel interconnect to the storage shelf, BMC, redundant power. Runs the StorageGRID Appliance Installer and, once deployed, the StorageGRID node software (this is not preinstalled — it's pulled from the Admin Node at deployment time).
E2860 storage controller shelf (4U) Two E‑Series E2800 controllers in duplex (active/active failover) configuration; five drive drawers holding 60×3.5" drives (2 SSD metadata drives + 58 NL‑SAS data drives); redundant power/fans.
Optional DE460C expansion shelves (4U each) Two IOMs + five drawers of 12 drives = 60 drives per shelf. Up to two shelves can be added (180 drives total per SG6060).

The all-flash sibling, SGF6024, uses the same SG6000-CN compute controller but pairs it with a 2U EF570 flash shelf (24 SSDs, no expansion shelf support).

4. Installation Walkthrough

4.1 Preparation (both appliance types)

  1. Confirm site meets power, cooling, weight, and rack-depth specs (check the NetApp Hardware Universe).
  2. Unpack and verify contents against the packing slip (appliance, rail kit, power cords).
  3. Gather tools: Phillips/flat screwdrivers, ESD wrist strap, correct transceivers/cables for your chosen link speed, a service laptop with a supported browser (Chrome 87+, Edge 87+, or Firefox 84+).
  4. Record planned IP addressing, switch ports, and bond modes for each network before you start cabling (see the worksheets in §5).
  5. Register the hardware on the NetApp Support Site using the chassis serial number.

4.2 Hardware install steps

  1. Install rails in the cabinet/rack, then slide the appliance onto the rails until the latches click.
  2. Cable the BMC management port (recommended, optional) and the Admin Network port(s).
  3. Cable the data network ports to your switches based on the bond mode you chose (Fixed vs Aggregate — see §6).
  4. SG6060 only: connect the Fibre Channel interconnect ports between the SG6000-CN and each E2800 controller, and SAS-cable any expansion shelves.
  5. Connect both power cords to separate PDUs and power the unit on. Confirm the power LED turns solid blue and no amber alarm LED lights up.
  6. Re-attach the front bezel only after the unit powers on successfully.

4.3 Software/node configuration

  1. Browse to the StorageGRID Appliance Installer (via DHCP-assigned IP, or via the temporary link-local address 169.254.0.1 on the spare management port) to set link speed, port bond mode, and IP addresses for each network.
  2. SG6060 only: use SANtricity System Manager (via the E2800 management port) to confirm the storage controllers and drives are healthy before proceeding.
  3. Optionally enable node encryption against an external Key Management Server (KMIP) before the node joins the grid.
  4. From the primary Admin Node's Grid Manager (or the Appliance Installer during first-time grid deployment), deploy the node as a Gateway/Admin Node (SG100) or Storage Node (SG6060) and let it join the grid.

5. Networking Types and IP Planning

Every appliance can connect to up to three logical StorageGRID networks, plus a separate hardware management network:

NetworkRequired?Purpose
Grid NetworkRequiredAll internal StorageGRID node-to-node traffic, across all sites/subnets.
Admin NetworkOptionalClosed network for system administration/maintenance; typically not routed between sites.
Client NetworkOptionalOpen network for S3/Swift client traffic, letting you keep the Grid Network isolated.
BMC management networkOptional (recommended)Out-of-band IPMI access to the hardware controller; can share the Admin Network or be fully independent.
For each network you plan to use, gather: DHCP vs static addressing, IPv4 address (CIDR), gateway, subnet list, switch port mapping, and (Grid/Client only) MTU and VLAN tag if used. The 11.5 documentation provides worksheet tables for exactly this purpose for the SG100/SG1000 and SG6000 chapters.

6. Port Bond Modes

Both appliance families use the same two bonding concepts for the Grid/Client data ports, plus a simpler scheme for the 1-GbE Admin management ports.

Fixed port bond mode default

Ports 1 & 3 bond for the Client Network; ports 2 & 4 bond for the Grid Network.

  • Active-Backup (default): one port active, the other a hot standby.
  • LACP (802.3ad): both ports form one logical channel for higher throughput; if one fails, throughput drops but the link stays up.

Aggregate port bond mode

All connected ports join a single LACP bond shared by Grid + Client traffic, distinguished by a unique VLAN tag per network.

  • Requires LACP-capable switches; if multiple switches are involved, they must support MLAG (or equivalent).
  • Maximizes throughput and adds failover paths versus Fixed mode.

Admin/management port bonding (1-GbE ports)

  • Independent mode (default): only the left management port connects to the Admin Network; the right port is free for a temporary local connection at 169.254.0.1.
  • Active-Backup mode: both ports bond into one logical, redundant connection to the Admin Network.
For a temporary local connection while Active-Backup is configured: unplug both management ports, plug into the right-hand port, and browse to 169.254.0.1.

7. BMC (Baseboard Management Controller)

Every model in this tutorial includes a BMC for out-of-band hardware monitoring/management over IPMI, reached through its own 1-GbE RJ-45 port. Through the BMC interface you can:

  • View boot-up status codes and hardware error/alarm history
  • Monitor power, fan, and temperature sensors
  • Perform remote power actions (power cycle, reset) when the node is unresponsive
  • Configure SNMP for alerting (note: as of recent StorageGRID releases, BMC SNMP configuration on SG6000/SG100/SG1000 requires an IP address rather than a fully-qualified domain name)

8. OS / Firmware Upgrade Processes

"OS upgrade" means different things depending on which layer of the appliance you mean. There are three distinct upgrade paths:

8.1 StorageGRID node software upgrade (applies to SG100 and SG6060 alike)

This is the grid-wide StorageGRID software version running on every node (including the appliance's internal OS image on its SSDs). It's performed centrally from the Grid Manager as part of a planned StorageGRID upgrade/hotfix and is documented separately from appliance hardware procedures — it rolls the same version out across all nodes, appliance or virtual.

8.2 SANtricity OS upgrade — storage controller firmware (SG6060 / SG6000 family only)

The SG6060's E2800 controllers (and SGF6024's EF570 controllers) run SANtricity OS, which must be kept at the version qualified in the NetApp Interoperability Matrix Tool. There are two supported methods, chosen based on the currently-installed version:

Current SANtricity OS versionUpgrade method
08.42.20.00 (11.42) or newerGrid Manager (online, rolling)
Older than 08.42.20.00 (11.42)Maintenance mode (offline, manual)

Grid Manager method (recommended path):

  1. Download the correct SANtricity OS file for your controller model (E2800 for SG6060, EF570 for SGF6024) from the NetApp Support site.
  2. In Grid Manager: Maintenance → Software Update → SANtricity OS.
  3. Browse to and upload the file; wait for upload & validation (don't rename the file — the name is part of validation).
  4. Enter the provisioning passphrase and click Start; accept the warning that the browser session may briefly disconnect.
  5. A health check runs first, confirming no node shows "Needs Attention."
  6. Approve each Storage Node (or Approve All) to queue it for upgrade — approved nodes upgrade one at a time, and approving stops services on that node before it reboots, so only approve nodes you're ready to take offline briefly.
  7. Monitor the SANtricity OS Upgrade Progress table until all approved nodes show Complete.
  8. NVSRAM is upgraded automatically alongside SANtricity OS — no separate NVSRAM file is needed.
You can't run a StorageGRID software upgrade or hotfix while a SANtricity OS upgrade is pending — the system redirects you back to the SANtricity OS page until it's finished. Never use generic E-Series upgrade instructions outside StorageGRID's documented process — doing so can make the appliance inoperable.

Maintenance mode method (for older SANtricity OS versions):

Used when the controller's current firmware is too old for the Grid Manager path. This is performed directly against the storage controller (via SANtricity System Manager while the node is placed into StorageGRID maintenance mode) rather than through Grid Manager's rolling upgrade flow. After this manual step brings the controller to 08.42.20.00 (11.42) or newer, all future upgrades can use the Grid Manager method.

8.3 BMC / BIOS firmware

Compute-controller BIOS and BMC firmware (covering the SG6000-CN, SG100, and SG1000 controllers) is updated separately from SANtricity OS and is typically bundled with specific StorageGRID hotfixes/releases — for example, SG6060 and SGF6024 appliances have been automatically upgraded to a specific qualified BIOS version as part of certain StorageGRID releases.
