A field guide to IP addressing

Every IP address is hiding
two questions inside one number.

Which network is this, and which host on it? The netmask is just the answer key — and once you can read it in binary, subnetting stops being memorization and starts being arithmetic.

01 · Foundations

Computers count in two digits. We count in ten. Everything starts with translating between them.

An IPv4 address is a 32-bit number. We write it in "dotted decimal" — four groups of decimal digits — purely for human convenience. The machine never sees the dots; it sees bits.

Place values, right to left

Just like the decimal system has a 1s, 10s, 100s place, binary has a 1s, 2s, 4s, 8s place — each one double the last. Click the bits below to see how a binary number adds up to a decimal value.

Why 8 bits per group? An IPv4 address is split into four 8-bit groups called octets. 8 bits gives 2⁸ = 256 possible values — 0 through 255 — which is why every number you've ever seen in an IP address falls in that range.

02 · The netmask

The netmask draws a line through the address: everything before it is the network, everything after is the host.

A netmask is also a 32-bit number — but it's not an address at all. It's a pattern of 1s followed by 0s. The 1s mark "this bit identifies the network." The 0s mark "this bit identifies the specific device on that network."

Why subtract 2 from the host count? In every subnet, the first address (all host bits = 0) is the network address — it names the subnet itself and can't be assigned to a device. The last address (all host bits = 1) is the broadcast address — it sends to every host on the subnet at once. Both are reserved, so usable hosts = 2(host bits) − 2. (The /31 and /32 cases below are the exceptions.)
03 · CIDR notation

"/24" is shorthand for "count the 1s." That's the entire notation.

CIDR stands for Classless Inter-Domain Routing. Before it existed (pre-1993), networks came in only three fixed sizes — Class A, B, and C — which wasted huge blocks of address space. CIDR replaced that with a simple idea: write the netmask as a slash followed by the number of leading 1-bits. /24 means "the first 24 bits are network bits," full stop — any boundary, any size.

05 · Worked example

Given an address and a CIDR, find everything else by hand.

Let's fully solve one: 172.16.50.130/26. No calculator — just the bits.

Convert the relevant octet to binary. /26 falls inside the third octet (it's past the first 24 bits; 26 − 24 = 2 bits into octet 3). So we need octet 3 — the value 50 — in binary.

50 = 32 + 16 + 2 → 00110010

Mark the network/host split. 24 of the 26 network bits are already spent on octets 1–3's positions, so only 2 more bits (within octet 3) are network bits — the rest of octet 3 (6 bits) plus all of octet 4 are host bits.

00110010 → network portion = 00, host portion = 110010

Zero out the host bits to find the network address. Keep the network bits, set every host bit to 0 (this includes octet 4).

00000000 = 0 → octet 3 becomes 0, octet 4 becomes 0

172.16.50.130 → 172.16.0.0/26

Set every host bit to 1 to find the broadcast address.

00111111 = 63 → octet 3 becomes 63, octet 4 becomes all 1s = 255

172.16.63.255

Count host bits to get the host count. /26 leaves 32 − 26 = 6 host bits. 2⁶ = 64 total addresses, minus 2 reserved = 62 usable.

62 usable hosts, 172.16.0.1 – 172.16.0.62
The faster shortcut, once you trust the binary: find which octet the slash lands in, then compute its "magic number" — 256 divided by 2(network bits in that octet). Here, /26 puts 2 network bits into octet 3, so the magic number is 256 ÷ 2² = 64. Round the address's value in that octet (50) down to the nearest multiple of 64 — that's 0 — and every octet after the boundary becomes 0 too. Same answer as the binary method, in two mental steps instead of five.
06 · Subnetting

Subnetting is just borrowing bits from the host side to make more, smaller networks.

Say you're given 192.168.1.0/24 and need to split it into 4 separate networks (e.g., 4 office floors, each on its own VLAN). Every time you move the slash one bit to the right, you double the number of subnets and halve the size of each one.

The pattern to notice: every subnet's range ends exactly 1 below the next subnet's start, and each network address is a multiple of the block size (64, in this case). This is why subnet boundaries always feel like "clean" numbers once you know the block size — they're not arbitrary, they're multiples.
07 · Good to know

A few address ranges and rules you'll bump into constantly.

Private (RFC 1918) ranges
10.0.0.0/816.7M hosts
172.16.0.0/121M hosts
192.168.0.0/1665K hosts

These never route on the public internet — your router uses NAT to translate them.

Reserved / special-use
127.0.0.0/8Loopback (localhost)
169.254.0.0/16Link-local (no DHCP)
0.0.0.0/0"Any address" / default route

169.254.x.x means a device's DHCP request failed — it self-assigned.

Common trap: a netmask must be a contiguous run of 1s followed by 0s — 255.255.255.0 is valid, but something like 255.0.255.0 (1s, then 0s, then 1s again) is not. That pattern is sometimes called a "wildcard mask" instead, and means something different (used in access-control lists, not subnetting).
08 · Check yourself

Three quick ones.

1. How many usable hosts does a /29 network provide?
/29 leaves 3 host bits (32−29). 2³ = 8 total addresses, minus 2 reserved (network + broadcast) = 6 usable.
2. What's the network address for 10.4.20.99/22?
/22's boundary falls in octet 3, with a magic number of 256−252=4. Multiples of 4 near 20 are 16 and 20 — since 20 is itself a multiple of 4, the network address is 10.4.20.0.
3. Which of these is NOT a valid netmask?
A valid netmask must be a contiguous run of 1s followed by 0s. 255.0.255.0 has 1s, then 0s, then 1s again — a discontiguous pattern, making it invalid as a netmask (though it could be valid as a wildcard mask in a different context).
