Ansible YAML Indentation Guide

This guide explains YAML indentation, alignment, list structures, document markers, and how Ansible interprets indentation.

1. What is YAML?

YAML stands for: 

YAML Ain't Markup Language

Ansible playbooks are written in YAML. YAML uses spaces and indentation to represent hierarchy instead of braces ({}) or XML tags.

2. YAML Document Start Marker (---)

The symbol: 

---

indicates the start of a YAML document.

Example

---
- name: Play 1

This tells YAML: 

Start a new document here

Is it mandatory?

No. But it is considered a best practice.

---
- name: Play 1

and

- name: Play 1

are both valid.

3. Meaning of Dash (-)

A dash represents an item in a list. 

tasks:
  - name: Task 1
  - name: Task 2

Hierarchy: 

tasks
├── Task 1
└── Task 2

4. Understanding Indentation

YAML uses spaces to represent parent-child relationships. 

tasks:
  - name: Install Apache
    yum:
      name: httpd
      state: present

Hierarchy: 

tasks
└── Task
    └── yum
        ├── name=httpd
        └── state=present

5. Complete Playbook Breakdown

---
- name: Play 1
  hosts: target_hosts

  tasks:

    - name: Task 1
      module_name:
        key: value

    - name: Task 2
      second_module_name:
        key: value

Hierarchy View

YAML Document
│
└── Play 1
    │
    ├── hosts
    │
    └── tasks
         │
         ├── Task 1
         │    └── module_name
         │         └── key=value
         │
         └── Task 2
              └── second_module_name
                   └── key=value

6. Standard Indentation Rules

Rule Description
Use spaces Always use spaces, never tabs
2 spaces Most common indentation standard
Consistent spacing Maintain the same indentation level
Lists use - Dash indicates list items
Children indent further Nested objects must be indented

7. Correct vs Incorrect Indentation

Correct

tasks:
  - name: Install Apache
    yum:
      name: httpd
      state: present

Incorrect

tasks:
- name: Install Apache
yum:
  name: httpd

This causes YAML parsing errors because hierarchy is lost.

8. Common YAML Errors

Error Reason
mapping values are not allowed here Wrong indentation
did not find expected key Missing spaces
found character that cannot start any token Tab character used
Syntax Error while loading YAML General formatting issue

9. Real Ansible Examples

Install Package

---
- name: Install Apache
  hosts: webservers

  tasks:

    - name: Install HTTPD
      yum:
        name: httpd
        state: present

Create File

---
- name: Create File
  hosts: all

  tasks:

    - name: Create file
      file:
        path: /tmp/test.txt
        state: touch

Copy File

---
- name: Copy Config
  hosts: all

  tasks:

    - name: Copy file
      copy:
        src: app.conf
        dest: /etc/app.conf

10. YAML Data Structures

Dictionary (Key-Value)

user:
  name: admin
  uid: 1001

List

packages:
  - httpd
  - nginx
  - git

List of Dictionaries

users:
  - name: john
    uid: 1001

  - name: mike
    uid: 1002

11. Best Practices

  • Always use spaces, never tabs.
  • Use 2-space indentation consistently.
  • Keep playbooks clean and readable.
  • Align child objects correctly.
  • Validate playbooks using syntax checks.
  • Use VS Code YAML extensions for validation.
  • Follow Ansible YAML style standards.

12. Interview Questions

Why is indentation important in YAML?

Indentation defines hierarchy and parent-child relationships. Incorrect indentation changes structure and causes parser errors.

What does --- mean in YAML?

It marks the beginning of a YAML document.

What does - mean in YAML?

It indicates a list item.

Can YAML use tabs?

No. YAML requires spaces only.

What is the standard indentation in Ansible?

2 spaces per level.

Quick Interview Answer

YAML uses indentation to represent hierarchy. The --- symbol marks the beginning of a YAML document, while - represents list items. In Ansible playbooks, plays, tasks, modules, and parameters are organized through indentation. Correct alignment is critical because YAML does not use braces or tags; it relies entirely on spacing to define structure.
