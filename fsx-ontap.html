01

What it is

The pitch in one line: the file system your storage team already knows, running as a managed AWS service instead of a rack you maintain.

FSx for ONTAP packages NetApp's ONTAP file system — the same software behind countless on-premises NetApp filers — as an AWS-managed offering. That means snapshots, clones, replication, and multi-protocol access aren't reimplemented from scratch; they're the real ONTAP capabilities, just without the racking, patching, or capacity planning. AWS handles provisioning, patching, and failover; you keep the operational vocabulary — volumes, SVMs, SnapMirror — that NetApp admins are already fluent in.

multi-protocol

NFS, SMB, iSCSI, and NVMe-over-TCP all access the same underlying data — no separate copies for Linux vs. Windows vs. block workloads.

elastic capacity

Storage grows and shrinks automatically. Throughput is a dial you turn, not a hardware order you place.

fully managed

AWS owns provisioning, patching, and hardware failover. You manage data, not infrastructure.

02

How a file system is organized

Four nested concepts, each one a container for the next.

FILE SYSTEM → HA PAIR(S) → STORAGE VIRTUAL MACHINE → VOLUMES
LayerRole
File systemThe top-level resource — analogous to an on-premises ONTAP cluster. You set SSD capacity, throughput, and the VPC it lives in.
HA pairTwo file servers in active/standby. Single-AZ file systems can scale out to up to 12 HA pairs for parallel performance; Multi-AZ systems run one HA pair spread across Availability Zones for resilience.
SVMA storage virtual machine — an isolated administrative and network boundary, useful for multi-tenancy or separating environments inside one file system.
VolumeThe logical container your data actually lives in. Thin-provisioned, so capacity is consumed only as data is written, not reserved up front.
03

Storage tiers and automatic tiering

The mechanism that makes "pay SSD prices for a small fraction of your data" actually work.

Every volume sits across two tiers. Primary storage is provisioned SSD — fast, sub-millisecond, and where active data lives. Capacity pool storage is the elastic, low-cost tier built for data that isn't being touched right now. ONTAP's tiering engine watches access patterns block-by-block and moves cold data down to capacity pool — and warms it back up to SSD the moment it's accessed again — without the application or user noticing the difference.

DATA BLOCKS MOVE BETWEEN TIERS AUTOMATICALLY, BASED ON ACCESS FREQUENCY

Storage efficiency

Compaction, compression, and deduplication run underneath both tiers. For general-purpose file sharing, typical savings run around 65% off the raw footprint — on SSD, capacity pool, and backups alike.

Thin provisioning

Volumes reserve nothing up front. Capacity is claimed as data is written and released back to the file system the moment it's deleted.

04

Data management, carried over from ONTAP

These aren't AWS reinterpretations — they're the same ONTAP capabilities storage teams already operate on-premises.

SnapMirror replication

Replicates files, metadata, and file-system configuration between ONTAP systems — including from on-premises straight into AWS — in minutes, making it a well-worn path for migration and disaster recovery.

FlexClone

Creates an instant, writable copy of a volume that shares data blocks with its parent. A clone consumes essentially no extra storage until it diverges — ideal for spinning up dev/test or staging copies of production data.

Snapshots

Point-in-time, space-efficient copies for fast recovery, taken on a schedule or on demand, layered on top of FSx's own automatic daily backups.

Autonomous Ransomware Protection

ONTAP's built-in anomaly detection watches for ransomware-like behavior and can automatically trigger protective snapshots when it sees signs of an attack.

05

How data gets accessed

One copy of data, reachable through whichever door each client needs.

SAME UNDERLYING DATA, REACHED VIA NATIVE PROTOCOLS OR AS S3 OBJECTS

The S3 Access Point capability is the newer piece here: it lets AI, ML, and analytics services that expect an S3 endpoint — Bedrock, SageMaker, Athena, Glue — read the same file data without a copy step, while the data itself never leaves the FSx file system.

06

Where it tends to get used

A

NetApp migration & disaster recovery

For shops already running ONTAP on-premises, SnapMirror makes AWS a replication target rather than a re-platforming project — no application changes required.

B

VMware workload migration

Built-in storage efficiency and data tiering are commonly cited as delivering significant cost savings when moving VMware-based NFS datastores into AWS.

C

Mission-critical databases

SQL Server and Oracle workloads get sub-millisecond latency plus space-efficient cloning — handy for instantly refreshing dev, test, or staging copies of production databases.

D

SAP HANA

FSx for ONTAP carries SAP HANA certification, pairing in-memory database performance requirements with ONTAP's data protection.

E

AI / ML and analytics on private data

Via S3 Access Points, file data already sitting in FSx for ONTAP can directly feed model training or GenAI applications without duplicating it into object storage first.

F

General-purpose file consolidation

One file service serving Linux, Windows, and macOS clients simultaneously — useful when teams have historically needed separate NAS systems per platform.
